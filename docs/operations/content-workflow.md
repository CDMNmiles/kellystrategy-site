# 资料整理与发布流程 V1

日期：2026年11月8日｜美国洛杉矶时间
状态：开发前执行规范；与数据模型共同使用。现阶段未宣称资料全量整理完成。

## 1. 工作单位与责任

每轮处理一个有边界的批次：明确来源范围、类型、版本／读取时间、目标页面、处理负责人及验收者。内部来源台账沿用已有资料库；公开仓库只接受经整理的发布内容。

同一对象只有一名写入负责人；其他Agent提交建议或批次结果。总控维护分类规则及冲突决定，独立验收者检查来源、公开范围与实际页面。Muse只按实际可访问能力接手任务，未收到实际结果时不得标记已执行。

## 2. 两条状态线

来源处理与网页发布分别记录，不使用一个“完成”状态概括所有工作。

| 来源状态 | 进入条件 | 下一步 |
| --- | --- | --- |
| `discovered` 已发现 | 有稳定来源标识及发现记录 | 读取原件或登记访问问题 |
| `extracted` 已提取 | 文本／结构提取结果及范围已保存 | 核对原文；图片和图表还需目视 |
| `verified` 已核对 | 原意、定位、版本、归属和疑难项已核实 | 提炼网页草稿或关联已有内容 |
| `needs-review` 待核 | 不可读、冲突、提取不全或归属不清 | 保留原因、负责人和下一动作 |
| `excluded` 已排除 | 与项目无关、经核验重复或其他明确原因 | 保留记录与指向，不删除原件 |

`extracted`不能等同`verified`。来源变化产生新版本或回到待核状态；保留旧核验记录。核实某一段落时标明范围，不把全文标为已核实。

| 网页状态 | 进入条件 | 是否进入公开构建 |
| --- | --- | --- |
| `draft` 草稿 | 已有内容对象，尚未完成检查 | 否 |
| `in-review` 待检查 | 正文、分类、关联与所需事实已备齐 | 否 |
| `ready` 可发布 | 事实与公开范围明确，发布数据校验通过 | 可导出至发布批次 |
| `published` 已发布 | 生产版本及实际访问已核验 | 是 |
| `revision-needed` 待修订 | 已发现影响准确性或可用性的变化 | 视影响保留准确部分或撤下该版本 |
| `withdrawn` 已撤下 | 有明确处置与旧网址去向 | 仅保留需要的状态说明或重定向 |

“可发布”不是要求每次重新征求用户许可；按任务已有授权和记录的公开范围推进。来源公开范围仍不明确时，仅该材料待核，其他已明确内容继续处理。

## 3. 每批操作

### A. 发现与留档

记录来源清单、查询／目录范围、分页是否结束、版本及账号覆盖。读取受限时写“未取得”，不以没有结果推断没有资料。保存调整前网站及YouTube对象状态，后续迁移使用原ID。

### B. 读取与核实

文字读取实际正文；演示按页核对；图片目视并保留原图定位；复杂图表不能只采集OCR。记录观点时期及事实性质。历史草稿不直接成为现行频道介绍，旧价格与旧联系信息不自动成为现行商业条件。

### C. 分类与编写

按四大主题给一个主归属，再关联子栏目、系列、专题、课程或工具。提炼有实质内容的简介，保留关键论点和必要背景。公开视频整理稿应标清是整理稿；未取得全文时不写成完整逐字稿。

### D. 公开数据导出

按`data-model.md`的白名单构造新对象。内部来源、审计证据和未公开材料只留在私有工作区。默认不把私人链接当公开“参考资料”。渲染公开页面、搜索索引及下载区前进行同样检查。

### E. 预览与发布

检查真实手机宽度、主要观看与咨询路径、目录与相关内容。实际确认播放器、工具及下载行为。通过后记录数据批次、代码提交与生产版本；正式网址实测后才标`published`。

### F. 对账与交接

交付本批范围、完成／待核／排除数量、生成页面、异常、实际修改、下一批入口。发出任务不是已完成，脚本通过不是内容核实完成。

## 4. 数量对账与覆盖

在已证明的来源范围内：唯一来源总数＝已核对＋待处理／待核＋明确排除，各项互斥。发现记录数、去重后的来源数、可公开内容数、生成页面数分别报告，不能混用。

| 检查 | 要求 |
| --- | --- |
| 来源覆盖 | 所有已获取来源均有处理记录；未访问账号与目录单列 |
| 重复 | 同一来源版本不重复入账；同名仅作候选提示 |
| 视频覆盖 | 视频ID去重；公开视频、会员、非公开、私享、Shorts与直播回放分别统计 |
| 发布覆盖 | 每个发布对象有归属、固定详情及可解释的来源关联 |
| 孤立关联 | 不存在无目标的课程、系列、工具或专题引用 |
| 范围声明 | “目录覆盖完成”和“全文资料完善完成”分别验收 |

样本适合验证分类与页面模板；不能据此宣布全量迁移。来源数量未知时不计算虚假的总体完成百分比。

## 5. 课程更新

课程在对应主题和課程中心展示同一记录。更新名称、模块、价格、交付、观看期限、会员／单购区别及公开咨询方式时，只改课程主记录，再检查所有入口。

价格没有现行核验依据时不显示旧数额；显示可用的咨询入口。咨询按钮携带课程名称并由观众自行发送。网站点击与实际咨询、成交分开记录。

更新后检查：试看权限正确、联系目标正确、二维码可读、微信号可复制、邮箱与WhatsApp链接可打开。测试过程不向他人发送消息。

## 6. 工具接入与版本

每个软件先登记实际代码／运行位置、用途、平台、版本与权利范围，再检查主要功能。按实际结果标为可使用、可试用、开发中或停止维护。

在线工具核查入口、移动端兼容与关键输入输出；桌面工具核查文件、平台、版本和使用说明。只有截图或历史讨论的项目保持候选，不显示可用按钮。

工具中心与百家樂分类页共用一个工具详情。更新版本时保留变更说明，核对旧下载链接是否仍可用；原链接移除后给出替代或明确状态，不能指向不相关软件。

## 7. 失效链接与权限变化

| 情况 | 处理 |
| --- | --- |
| 网站内链404 | 检查slug、引用与重定向，修复后再发布 |
| YouTube不可嵌入 | 页面显示受限说明，保留已确认有效的官方观看入口 |
| 视频删除或转私享 | 核对真实状态，保留必要介绍或撤下播放入口，更新关联列表 |
| 会员／购买要求 | 明确观看条件，不尝试绕过权限 |
| 来源403、登录要求、超时 | 标记访问受限／待重查，不直接判定内容已删除 |
| 外部来源迁移 | 核实新来源与原内容一致，记录改前／改后 |
| 工具或下载不可用 | 暂停操作按钮，保留说明并标状态，待实际修复后恢复 |
| 课程信息过期 | 更新主记录，检查各入口与搜索摘要，不擅自改写交易条件 |

仅结构检查无法证明第三方播放器实际运行；需人工完成代表性播放及受限状态检查。自动HTTP检查不得将登录跳转或200状态一律当成内容可用。

## 8. YouTube同步与回滚

先形成播放列表与首页的改前／目标映射，再分批执行。复用视频ID和已有有效播放列表ID，避免删除重传。每项记录对象ID、改前值、改后值、执行时间、实际结果与例外。

按计划与实际成员、顺序核对，不只检查列表名称。会员和私享状态单独核实。网站分类更细时通过关联展示，不要求YouTube实现不存在的层级。

发布失败时保留旧生产版本；分类调整失误依据快照恢复。回滚网页数据不抹去本批内部处理记录。若任何受限材料误入公开产物，应先撤下受影响内容，再清理相关缓存、索引和公开历史暴露范围，记录实际处理结果。

## 9. 交接模板与完成定义

每项任务交接：任务ID、目标、输入版本、负责范围、输出对象、修改结果、验证证据、待核事项、下一责任人。内部证据与公开文档分开，公开仓库仅存执行规范与允许公开的结果。

一批资料完成的标准：来源范围可说明；数量可对账；原文与草稿有可追溯关系；公开范围明确；发布数据校验通过；页面及关键操作实际检查；生产状态如实记录；未完成项有去向。

本流程未创建自动同步、后台持续任务或新的资料服务。后续如实现自动化，应另记录运行入口、访问范围、失败处理和实测结果。
